# 埋入缺陷清单

目标库 `target/dl645.c` 模拟现场集抄终端（集中器）对从站上行报文的解析路径。
下列缺陷全部是**有意埋入**的，每一处在源码里都有 `DEFECT Dxx` 注释；用
`-DDL645_FIXED` 编译即得到修复版，供回归流程使用。

所有缺陷都属于同一类真实故障模式：**索引/长度没有按表的实际尺寸或实际缓冲区校验**。
它们不是教学用的 `strcpy` 溢出，而是规约解析代码里最常见的那种“表比域宽小一格”。

| 编号 | 类别 | 位置 | 缺陷 | 触发方式 | ASan 报告类型 |
|------|------|------|------|----------|----------------|
| D01 | 长度域 | `parse_frame_2007` | 长度域 `L` 是 1 字节，取值 0..255；`data_copy[200]` 只检查了“报文里有 L 字节”，没检查 `L <= 200`，`memcpy(data_copy, b+10, L)` 直接越界写栈 | 2007 帧 `L = 201..255`，且报文长度与之匹配 | stack-buffer-overflow (WRITE) |
| D02 | 长度域 | `parse_frame_1997` | 1997 兼容路径用两个字节拼出 `L2`，只检查 `L2 <= 200`，没检查“输入里真的有 11+L2 字节”，`memcpy(copy, b+11, L2)` 读越界 | 2007 解析失败后进入 1997 路径，`L2` 大于剩余字节数 | heap-buffer-overflow (READ) |
| D03 | 校验和 | `checksum_retry` | 校验和错误时查 16 项重传策略表，索引写成 `calc & 0x1F`（0..31） | 构造校验和错误的帧，使 `calc` 落在 16..31 | global-buffer-overflow (READ) |
| D04 | BCD | `addr_decode` | 地址按 BCD 解码，但查 10 项的字符表时索引取自 4 bit 半字节（0..15） | 地址任一字节的半字节为 `0xA..0xF` | global-buffer-overflow (READ) |
| D05 | BCD | `dispatch_item` | 电能量数据项的小数位是 BCD 半字节（0..15），查 8 项小数倍率表 | `DI=0x9010` 且小数位字节高半字节为 `0x8..0xF` | global-buffer-overflow (READ) |
| D06 | 控制码 | `dispatch` | 控制码分类表只有 24 项，索引用 `ctrl & 0x1F`（0..31） | 控制码 `0x18..0x1F` / `0x38..0x3F` / `0xF8..0xFF` 等低位落在 24..31 | global-buffer-overflow (READ) |
| D07 | 重传缓存 | `retransmit_cache` | 校验和错误时先 `free(st->last)`，随后又向已释放的缓冲区 `memcpy` 上一帧原始报文 | 先送一帧合法帧填满缓存，再送一帧校验和错误的帧 | heap-use-after-free |
| D08 | 流式记账 | `record_batch` | 4 槽批处理窗口用 1 基的帧计数寻址，第 5 帧写 `batch[4]` | 单次输入里连续 5 帧以上合法帧 | heap-buffer-overflow (WRITE) |

## 设计要点

* **同根因归并**：D04 的高半字节与低半字节越界分别发生在 `dl645.c:48` 和
  `dl645.c:49`，若按 ASan 的 `file:line` 分桶会裂成两个桶。分桶键取
  `(ASan 类型, 出错函数)`，因此它们稳定落入同一个桶。
* **不同根因拆分**：D01、D02、D08 都是堆/栈越界，但出错函数分别是
  `parse_frame_2007`、`parse_frame_1997`、`record_batch`，不会被并成一个桶。
* **可达性**：8 个缺陷都需要“结构正确、校验和/长度可辨”的报文才能走到，
  因此变异器必须懂帧结构：改完数据域后自动重算长度域与校验和，只有需要
  走错误分支时才故意破坏校验和或让长度域与实际字节数不一致。
* **独立触发**：`tests/test_defects.py` 对每个缺陷给出一条手工构造的最小报文，
  逐个验证修复前必崩、修复后不崩。

## 修复版

`DL645_FIXED` 下的对应修复：

| 编号 | 修复 |
|------|------|
| D01 | `L > DL645_MAX_DATA` 直接返回长度错误 |
| D02 | 拷贝前检查 `11 + L2 <= n` |
| D03 | 索引改为 `calc & 0x0F` |
| D04 | 半字节 > 9 时输出 `'?'`，不查表 |
| D05 | 索引改为 `dec & 0x7` |
| D06 | 索引改为 `idx % 24` |
| D07 | `free` 后把指针置空并清长度 |
| D08 | 索引改为 `frames % DL645_MAX_BATCH` |
